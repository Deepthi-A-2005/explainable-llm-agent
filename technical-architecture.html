System design

A small pipeline with explicit boundaries.

The local prototype separates context, scoring, entity extraction, explanation, and response generation so each decision can be inspected and tested independently.

Implemented

Current research artifact

  • Deterministic intent scoring with weighted keyword/phrase cues.
  • Explicit confidence normalization and abstention threshold.
  • Entity extraction with character offsets.
  • Bounded context carryover (last four user turns) for short, weakly specified follow-ups.
  • Explanation data derived from the same scoring pass.
Future backend

LLM / RAG upgrade path

  • Replace local response adapter with a real model service.
  • Add retrieval with source IDs and citation attribution.
  • Use SHAP/LIME for suitable classifier components.
  • Use attention analysis only where the model architecture supports a meaningful interpretation.
  • Compare neural routing against the deterministic baseline on the same evaluation protocol.
Engineering principles

Why this structure?

01

Auditable

Every explanation points to an actual feature or context contribution instead of an invented reasoning narrative.

02

Replaceable

The response layer can later call an LLM/RAG service without changing the research-facing explanation contract.

03

Reproducible

No external API key is needed for the current prototype, so reviewers can run the same local behavior.

Architecture is intentionally explicit so future model upgrades can be evaluated against a transparent baseline.
